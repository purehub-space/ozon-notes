01

整书知识树

fq-book（docs/）
▶ ① 基础概念：代理 · 隧道 · VPN · 墙4
代理Proxy应用层转发，只处理交给它的流量，不创建虚拟网卡。书里第一句就点破它与 VPN 的最大区别。
隧道Tunnel把流量加密封装成一条专用通道送出去——SS / VMess / Trojan 本质都是隧道协议。
VPNVPN创建虚拟网卡（TUN/TAP），接管整个网络栈，所有流量默认进隧道。代表：WireGuard、OpenVPN。
封锁GFW 机制书里把墙定义为「高性能分布式入侵检测维稳系统」：DNS 污染、TCP RST、SNI/SSL 阻断、IP/端口封锁四种手段。
▶ ② 协议与工具7
ss Shadowsocks经典代理协议：客户端做 SOCKS 端口并兼容 HTTP；链接格式 ss://method:password@server:port（base64）。
ssr SSRSS 的升级版，加了「协议 + 混淆」（如 auth_sha1_v4 / tls1.2_ticket_auth）；链接格式 ssr://ip:port:protocol:method:obfs:password。
v2ray V2Rayvmess 协议：UUID + alterId + 传输协议（kcp/ws）+ 伪装类型；链接格式 vmess:// base64 JSON。
ssh SSH Tunnel借 SSH 22 端口做 SOCKS/HTTP 转发（书用 Bitvise 客户端配置）——被墙特征识别明显，易被封。
wg WireGuard新一代 VPN 协议，高性能，TUN 虚拟网卡接管全栈；书里以 TunSafe 客户端演示。
ovpn OpenVPN / Betternet传统 VPN 软件线：OpenVPN 已被 GFW 特征识别重点封杀；GateVPN 表格对比 SSL-VPN / L2TP / OpenVPN / MS-SSTP。
px Proxifier / Privoxy本地流量接管类工具：Proxifier 按进程强制走代理；Privoxy 做 HTTP 过滤代理。
▶ ③ DNS 与 Hosts5
污染DNS 污染墙对敏感域名返回伪造 IP/黑洞地址，解析到错误目标——UDP 53 端口的应答可被篡改。
劫持DNS 劫持运营商/路由器在解析应答里插广告或重定向（与墙无关，是商业行为）。
hosts Hosts本地静态「域名→IP」映射，绕过 DNS 查询；对「域名被污染但 IP 未封」的站点有效。
dnscrypt DNSCrypt加密 DNS 查询，防篡改、防嗅探；书里推荐 baidns.cn 等 DNS 配合使用。
最优解远程 DNS把域名解析交给海外节点（代理内解析），拿真实 IP——从根源绕过污染，是代理链路里的默认做法。
▶ ④ 链接与订阅3
解析节点链接格式ss:// 、ssr:// 、vmess:// 都是 base64 编码的「服务器参数串」；解码即得 method、password、server、port、UUID 等。
分享二维码 / 链接把编码串嵌进二维码或链接，客户端扫码/粘贴即可导入（SSR 可兼容 SS 链接，反之未必）。
订阅订阅源一条订阅 URL 自动更新整个节点池——正是「代理池」的喂料方式，mihomo 的 proxy-providers 原生支持。

获取找节点的方式搜索引擎 / GitHub / Telegram 频道 / 镜像站 / 免费账号站——书里列了十几种渠道，附「挖矿风险、链接失效」提示。
自建自建线路Heroku 一键部署 ss/v2ray 服务器、国外 VPS 自搭（ss-server 章节），适合稳定长期使用。
防封多线路组合单一方式随时可能断网：web 代理 + 代理插件 + DNSCrypt + 多个节点互相接力，形成「节点网」不易断。
进阶指纹浏览器代理 IP + 指纹浏览器组合，用于跨境电商多账号运营场景（与咱们 Ozon/TikTok 业务直接相关）。

02

流量如何被转发到「流量池」

从「你的手机/服务器」到「目标站」，流量经过 5 个环节。第 2–4 环是代理真正干活的地方：本地收流 → 规则分流 → 加密出境 → 节点代访。

接入本地端口手机连 WiFi 时手动设代理，或服务器 export HTTPS_PROXY=http://127.0.0.1:7890；流量先进本地客户端。
规则引擎分流mihomo 按「域名/IP/进程」规则匹配：国内直连、国外走节点、黑名单强制代理——这就是「PAC 的高级版」。
加密出境选中的节点参数（协议+密码+服务器）从配置/订阅里读取；流量加密封装，墙看到的是「到某服务器的加密流」。
节点代访海外节点解密请求，向目标站发起真实连接——目标站记录的是节点 IP，不是你的。
原路返回响应经同一隧道加密传回本地客户端，解密后交给应用。全流程对应用透明。

「流量池」本质 = 一批节点的集合。机场把几十台上游服务器编成池，订阅链接定时刷新节点列表；你手机/服务器上的客户端只是「入口 + 调度器」，真正出网的是池里的节点。

03

SSH：远程操控 ≠ 端口转发

SSH 是同一个协议、两种用法。区别一句话：远程操控是「你在服务器里做事」，端口转发是「让流量借你的隧道过路」。书里 SSH-Tunnel 章节演示的是第二种。

远程操控（控制面）

  • 登录到服务器上执行命令、读写文件：交互式 shell、scp/sftp 传文件
  • 命令：ssh user@server # 登录 scp file user@server:/path # 传文件
  • 本质：你在远端主机上「有了一双手」，操作的是服务器的状态
  • 常见场景：管理 VPS、部署代码、运维排查——跟「上网」无关

端口转发（数据面）

  • 让流量借道 SSH 加密隧道过路，三种模式：
  • -L 本地转发：本地端口 → 隧道 → 固定目标ssh -L 8080:internal.site:80 user@server
  • -D 动态转发：本地开一个 SOCKS5 代理，任意目标（书里 Bitvise 的 SOCKS/HTTP proxy forwarding 就是它）ssh -D 1080 user@server
  • -R 远程转发：把远端端口指回本地（内网穿透）ssh -R 9000:localhost:3000 user@server
  • 本质：流量不落地，只是「穿隧道换出口」——这才是代理
为什么被墙盯上SSH 隧道 vs 专业代理SSH 固定 22 端口 + 协议指纹明显，GFW 容易特征识别并封杀；而 SS/VMess/Trojan 是「为隐蔽而生」：随机端口 + 加密 + 混淆/伪装（把流量扮成普通 HTTPS）。这也是书里把 SSH 隧道列为「入门可试、长期易挂」的原因。
04

DNS 相关的概念

1 · resolution

域名解析流程

输入域名 → 系统 resolver → 递归 DNS → 根/权威服务器 → 返回 IP。解析结果决定你「连到哪台服务器」。

2 · poisoning

DNS 污染

墙对敏感域名直接返回伪造 IP / 黑洞地址，让你连去错误目标。UDP 53 明文查询极易被篡改——这是「打不开」最常见的第一道墙。

3 · hijacking

DNS 劫持

运营商/路由器在解析应答里插广告或重定向（国内宽带走 HTTP 常遇到）。与墙无关，是商业行为，换公共 DNS 可解。

4 · hosts

Hosts 本地映射

本地「域名→IP」静态表，绕过 DNS 查询。对「域名被污染但 IP 没封」的站点有效；IP 一旦被封则无效。

5 · dnscrypt / DoH

加密 DNS

DNSCrypt、DoH 把查询包加密，防篡改防嗅探——解决「查询路上被动手脚」，但解决不了「IP 层封锁」。

6 · remote dns

远程 DNS（代理内解析）

把域名交给海外节点解析、拿真实 IP 再回传——从根源绕开污染，是代理链路里的标准做法（mihomo 默认开启）。

一句话总结DNS 三兄弟改 hosts / 换 DNS = 只治「解析层」；加密 DNS = 治「查询被篡改」；真正干净的是「让墙外的节点做解析」。书里原话提醒：改 DNS 只能防劫持、防污染解析，解不了 IP 被封。
